# Windows 可访问性验收基准

QADB 的桌面界面由 Compose Desktop/AWT 承载。Windows 验收以 Java Access Bridge 配合 NVDA 为主，不把普通 UI Automation 控件树是否完整作为唯一结论。

## 基准范围

- 首页设备连接区：标题、连接状态、刷新与无线连接动作。
- 侧边栏：导航项名称、按钮角色、当前选中状态、禁用状态和键盘焦点。
- AI Agent：设备就绪状态、模型就绪状态、输入框、唯一主操作和动态错误。
- 模型配置：输入字段名称、测试连接动作、测试结果和错误提示。

## Windows 手工验收

1. 启用 Java Access Bridge，启动 NVDA 后再启动 QADB。
2. 分别在 960×640、1200×800、1440×900 下检查亮色/深色与中文/英文。
3. 仅使用 Tab、Shift+Tab、Enter、Space 和方向键遍历界面。
4. 确认 NVDA 朗读控件名称、角色、选中或禁用状态；焦点必须始终可见，且不进入禁用按钮。
5. 断开设备，确认无设备状态会被朗读，并可直接刷新设备、发起无线连接或返回首页排查。
6. 打开 AI Agent，依次验证“连接设备 → 配置视觉模型 → 测试连接 → 发送第一条指令”；设备或模型未就绪时不能误发送，草稿不得丢失。
7. 触发模型测试失败与 Agent 动态错误，确认错误出现时 NVDA 会主动播报。

## 框架升级约束

如果问题能够确认由当前 Compose Desktop 版本导致，应在独立 PR 中升级和验证 Compose；不要把框架升级与业务交互改动放入同一个 PR。
