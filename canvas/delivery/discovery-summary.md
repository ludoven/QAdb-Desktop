# QADB AI Agent 页面 · 设计需求摘要

> 文档用途：作为 AI Agent 页面原型设计的输入基准，供设计执行阶段参考。

## 一、五要素结论

| 维度 | 结论 |
|------|------|
| **场景（Surface）** | AI Agent 工作台 —— PC 桌面应用复合页面（1280×800 起步，建议 1440×900 基准），单页多面板工作台，非常规网页落地页 |
| **受众（Audience）** | Android 开发者 / 测试人员 / Android TV 盒子调试人员；B2C 专业工具用户，技术素养高、审美预期偏开发者工具，讨厌花哨与装饰性元素 |
| **调性（Tone）** | 专业、克制、工具感。参考 **Linear / Raycast / Warp / VS Code** 开发者工具美学：低饱和背景、清晰层级、数据密度、克制的高亮色。倾向 **Modern Minimal（现代极简）+ Tech Utility（技术工具感）** 的融合，避免 Brutalist 的实验性与 Soft Warm 的亲和力 |
| **品牌（Brand Context）** | 有既有品牌色：**QADB 蓝 #2196F3**。非全新品牌，需保留品牌识别但升级现代感。建议：保留蓝色作为「主操作 / 焦点 / AI 状态」强调色，但调整页面基底为中性深/浅色系，让蓝成为点睛而非大面积填充 |
| **规模（Scale）** | 单页复合工作台：核心对话流 + 实时设备画面 + 任务/状态面板三区联动。桌面优先，无移动端诉求；交互复杂度中高（对话流、视觉观察模式开关、Token 计数、任务进度、设备镜像、工具调用历史） |

## 二、关键功能清单

### A. 必须保留（现有能力的底线）

| 功能 | 现状 | 保留理由 |
|------|------|---------|
| 左侧导航栏（220px，8 菜单 + Logo + 已连接设备卡） | 已有 | QADB 全局信息架构的一部分，保持跨页面一致性 |
| 顶部状态栏（设备型号 / Android 16 API 36 / Wi-Fi / 电量 / ADB 在线） | 已有 | 调试工具的关键设备上下文，须常驻可见 |
| 主对话流（用户提问 → AI 回复） | 已有 | 核心交互载体，不可动摇 |
| 底部输入区 + 快捷按钮（打开设置 / 截图识别） | 已有 | Agent 指令入口，须保留且强化 |
| 新任务按钮 | 已有 | 多任务会话能力 |
| 右侧实时设备画面镜像 | 已有 | 本工具区别于普通聊天机器人的核心差异点 |
| 视觉观察模式（Live device observation + Page id + changed 状态） | 已有（被弱化） | **核心 Beta 能力**，须从角落标签提升为一级信息 |
| Token 计数（45449 Token · 压缩 0 次） | 已有 | 专业用户关注成本与上下文，须清晰呈现 |

### B. 应加强（补齐 AI Agent 应有信息）

| 功能 | 建议 |
|------|------|
| **任务执行进度** | 对话中插入任务状态流：待执行 → 执行中 → 完成/失败/需确认；失败时给出原因与重试 |
| **工具调用历史（Tool calls）** | 展示 Agent 每一步调用了什么（如 `am start` / `input tap` / `screencap`），带时间戳与参数摘要，可展开/折叠 |
| **思考链（Reasoning / Chain of thought）** | 轻量呈现 Agent 的推理过程，默认折叠、可展开，体现专业感而非黑盒 |
| **视觉观察模式状态机** | 从「角落小标签」升级为：模式开关 + 当前观察页面 id + 变更状态 + 最近一次观察时间 + 观察频率 |
| **Token 消耗可视化** | 从一行文字升级为小型计量条（当前用量/上限）+ 压缩次数徽标 |
| **任务历史/会话切换** | 支持在对话中新建任务并保留历史会话入口 |
| **风险操作确认** | 涉及设备敏感操作（发送消息、安装卸载）时，在对话流内做内联确认卡片 |

## 三、信息架构建议（页面分区）

以「**三栏工作台**」为基准骨架（1280 宽下可压缩右侧，1440 宽为最佳）：

```
┌──────────┬─────────────────────────────┬──────────────────────┐
│ 左侧导航  │         中央对话区           │       右侧设备面板     │
│ 220px    │       （弹性 480–640px）     │       （约 400px）     │
│          │                             │                      │
│ Logo      │  ┌─ 会话标题 + 任务状态条 ─┐ │  ┌─ 设备画面镜像 ────┐ │
│ 8 菜单     │  │ 对话流（消息 + 工具调用   │ │  │ 实时屏幕 + 状态徽标 │ │
│          │  │  + 思考链 + 任务进度）    │ │  │（Page id·changed）│ │
│ ──────   │  └─────────────────────────┘ │  └──────────────────┘ │
│ 已连接设备  │  ┌─ 输入区（钉住底部）──────┐ │  ┌─ 视觉观察模式 ────┐ │
│ 卡片      │  │ 输入框 + 快捷按钮 + 发送  │ │  │ 开关 + 观察状态    │ │
│          │  └─────────────────────────┘ │  └──────────────────┘ │
│          │                             │  ┌─ Token / 上下文 ───┐ │
│          │                             │  │ 计量条 + 压缩次数   │ │
└──────────┴─────────────────────────────┴──────────────────────┘
┌──────────────────────────────────────────────────────────────────┐
│ 顶部状态栏（跨栏通栏）：设备 · 系统 · 连接 · 电量 · ADB 状态        │
└──────────────────────────────────────────────────────────────────┘
```

分区职责划分：

1. **顶部状态栏（通栏，约 40–48px）**：设备上下文常驻。右对齐放 ADB 在线状态（绿点/灰点）。
2. **左侧导航（220px 固定）**：保持现有结构不变，仅做视觉升级（选中态、图标、间距）。
3. **中央对话区（弹性）**：
   - 顶部：会话标题行 + 当前任务状态（进行中/待确认）；
   - 中部：对话流，**工具调用、思考链、任务进度以卡片/时间线形式内联**，与消息同流；
   - 底部：**输入区钉住视口底部**（修复遮挡问题），输入框 + 快捷按钮 + 新任务 + 发送。
4. **右侧设备面板（约 400px，可折叠）**：
   - 上：实时设备画面镜像，顶部悬浮 Page id + changed 徽标；
   - 中：**视觉观察模式**（大开关 + 状态说明，核心 Beta 能力显性化）；
   - 下：Token 消耗计量 + 上下文统计，底部收起可腾出空间。
5. **信息密度原则**：设备画面与 Token 状态从「低密度大字报」改为「紧凑但可扫读」的层次结构；次要信息用次级文字色 + 更小字号，避免抢视觉重心。

## 四、风险与约束

| 类别 | 内容 |
|------|------|
| **技术约束** | Compose Multiplatform（桌面三端），需沿用现有组件体系；设备画面镜像为实时流，注意帧率与内存，右侧面板避免过重动效 |
| **品牌约束** | 保留 QADB 蓝 #2196F3 作为强调色，但整体应从基础 Material 风格升级；不引入与品牌无关的整套新配色 |
| **信息过载风险** | 新增思考链 / 工具调用 / 任务进度易堆叠，需默认折叠 + 可展开，避免淹没主对话流 |
| **遮挡问题（现状缺陷）** | 输入区悬浮导致对话被遮挡 → 新布局必须保证输入区固定且对话流留出底部安全间距（或可滚动到底不被遮挡） |
| **视觉观察模式命名** | 是 Beta 核心能力，但词面晦涩（Live device observation / Page id / changed），需在 UI 上用一句话解释「AI 正在看你的屏幕」 |
| **语义一致性** | 设备操作类 AI 回复需带「已执行/失败」的明确状态色（成功绿 / 失败红 / 进行中蓝），不得含糊 |
| **多端一致性** | Windows / macOS / Linux 下字体渲染与窗口装饰不同，设计需避免依赖单一平台特性（如毛玻璃仅在部分平台可用） |

## 五、设计哲学（定调）

**「让 Agent 的工作透明可见，让设备的状态一目了然。」**

—— 这是一个工具，不是一个聊天玩具；所有新增信息（思考链、工具调用、Token、观察状态）都应服务于「专业用户信任并掌控这个 Agent」这一目标，克制的视觉让数据本身说话。
